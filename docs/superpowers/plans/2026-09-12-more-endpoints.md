# okta-cli 19.1.0: more endpoints

**Goal:** Add the remaining high-value Okta management API families as CLI groups, reusing `defineResource` (src/commands/resource.ts) and the conventions of the 19.0.0 code.

**Conventions (read src/commands/policies.ts, authenticators.ts, roles.ts, platform.ts first):**
- Every group is registered from `src/cli/program.ts` (`registerX(program, ctx)`), imported alphabetically with the others.
- Use `defineResource` for list/get/add/replace/delete/activate/deactivate. Extra subcommands go on the returned `Command` with `addOutputOptions(addVerbose(...), FIELDS)` and `action(ctx, handler)`.
- Nested resources: resolve the parent with `resourceGet(client, SPEC, arg)` then hit `${SPEC.path}/${parent.id}/...`. Name lookups on nested items use `selectField` like `getRule` in policies.ts; swallow only `OktaApiError`.
- Every file gets a `tests/commands-<group>.test.ts` with (a) a `knownPath()` test for every path used, (b) one mock-server test per subcommand asserting method, path, query/body and the printed default table (see tests/commands-policies.test.ts and tests/fixtures/{server,ctx}.ts).
- String-returning commands (revoke/delete) get only `addVerbose`.
- Use `client.get`, `client.getAll(path, { query, listKey, max })`, `client.json(method, path, { body, query })`. Body input is always `-b/--body <json|FILE:path>` plus `-s/--set k=v` via `parseBody` (error `Provide -b and/or -s` when both empty).
- Default table fields: only fields Okta actually returns in list responses (check `src/okta/schema.d.ts` for the schema).
- Never write the literal patterns `password:` or `password=` in files (a local filter mangles them).
- Commit message per task as given; end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. `bun run check` green before each commit.

## Task 1: `auth-servers` (src/commands/auth-servers.ts, tests/commands-auth-servers.test.ts, commit `feat: authorization servers`)

- `AUTH_SERVERS: ResourceSpec` = `{ name: "auth-servers", description: "Custom authorization servers (OAuth 2.0 / OIDC)", path: "/authorizationServers", singular: "authorization server", nameField: "name", defaultFields: "id,status,name,audiences,issuer", lifecycle: true, listOptions: [{ flags: "--limit <n>", param: "limit", description: "page size" }] }` (spec list supports `q` and `limit`; the generic `-q` already covers `q`).
- Subcommands (all take `<server>` = id or unique name substring):
  - `scopes <server>` GET `/scopes` (fields `id,name,displayName,default,consent,system`); `scope-add <server> -b/-s` POST; `scope-delete <server> <scope-name-or-id>` DELETE (lookup by `name`).
  - `claims <server>` GET `/claims` (fields `id,name,claimType,valueType,status,alwaysIncludeInToken`); `claim-add <server> -b/-s` POST; `claim-delete <server> <claim-name-or-id>` DELETE.
  - `policies <server>` GET `/policies` sorted by priority (fields `id,status,priority,name`); `policy-add <server> -b/-s` POST; `policy-delete <server> <policy-name-or-id>`; `policy-activate` / `policy-deactivate <server> <policy>` POST `/policies/{id}/lifecycle/{verb}`.
  - `rules <server> <policy>` GET `/policies/{pid}/rules` sorted by priority (fields `id,status,priority,name,type`); `rule-add <server> <policy> -b/-s`; `rule-delete <server> <policy> <rule>`.
  - `clients <server>` GET `/clients` (fields `client_id,client_name`); `tokens <server> <clientId>` GET `/clients/{clientId}/tokens` (fields `id,status,issued,expiresAt,userId,scopes`); `tokens-revoke <server> <clientId> [tokenId]` DELETE all or one, returns a string.
  - `keys <server>` GET `/credentials/keys` (fields `kid,status,use,alg`); `rotate-keys <server> --use <kid>` POST `/credentials/lifecycle/keyRotate` body `{ use: ["<kid>"] }` (Okta expects `use: ["NEXT"]`... check schema `JwkUse`; if the schema says `use` is an enum, use option `--use <sig|enc>`... keep it exactly as the schema defines and test the body).
- README: add `auth-servers` to the group list and one quickstart line (`okta-cli auth-servers scopes default`).
