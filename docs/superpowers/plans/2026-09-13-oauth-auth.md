# okta-cli 19.4.0: OAuth 2.0 service-app authentication (private_key_jwt, optional DPoP)

**Goal:** Let a config profile authenticate to the Okta management API with an OAuth 2.0 service app (client credentials + `private_key_jwt`) instead of an SSWS API token, including orgs that require DPoP. Every existing command keeps working unchanged; SSWS profiles stay the default.

**Conventions:** as the earlier plans in docs/superpowers/plans/ (read the Conventions section of 2026-09-12-more-endpoints.md). Never write the literal patterns `password:` / `password=`.

**Background (verified against Okta docs, "OAuth 2.0 for Okta API" / "Implement OAuth for Okta with a service app"):**
- Token endpoint: `POST {orgUrl}/oauth2/v1/token`, `Content-Type: application/x-www-form-urlencoded`, form fields `grant_type=client_credentials`, `scope=<space separated okta.* scopes>`, `client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer`, `client_assertion=<JWT>`.
- Client assertion JWT: header `{ alg: "RS256", kid }`, claims `{ iss: clientId, sub: clientId, aud: "<token endpoint URL>", iat, exp: iat+300, jti: random }`, signed with the service app's private key (JWK or PEM, RSA; also accept ES256 when the key is EC).
- Response `{ token_type: "Bearer" | "DPoP", expires_in, access_token, scope }`. Use `Authorization: Bearer <token>` (or `DPoP <token>` when DPoP).
- DPoP (verified against the Okta DPoP guide for the Okta resource server): when the profile has `dpop: true` the token request always carries a `DPoP` proof header; Okta answers the first attempt with 400 `{ error: "use_dpop_nonce" }` plus a `dpop-nonce` response header, and the request is repeated once with `nonce` in the proof. If a profile without `dpop` gets 400 `invalid_dpop_proof` (app requires DPoP), switch to DPoP automatically and continue. Proof format: JWT header `{ typ: "dpop+jwt", alg, jwk: <public JWK of an ephemeral key pair> }`, claims `{ htm: "POST", htu: tokenEndpoint, iat, jti, nonce }`. Every API request then needs `Authorization: DPoP <token>` plus a `DPoP` proof JWT with `htm`, `htu` (URL without query), `iat`, `jti`, `ath` = base64url(sha256(access_token)), and `nonce` when the resource server returned one (`dpop-nonce` header on a 401 with `WWW-Authenticate: DPoP error="use_dpop_nonce"`); retry once with the nonce.
- Scopes list for reference in `--scopes` help: `okta.users.read okta.users.manage okta.groups.read okta.groups.manage okta.apps.read okta.apps.manage okta.logs.read okta.policies.read okta.policies.manage okta.roles.read okta.roles.manage okta.schemas.read okta.schemas.manage okta.authenticators.read okta.authenticators.manage okta.idps.read okta.idps.manage okta.devices.read okta.devices.manage okta.orgs.read okta.orgs.manage okta.sessions.read okta.sessions.manage okta.factors.read okta.factors.manage okta.eventHooks.read okta.eventHooks.manage okta.inlineHooks.read okta.inlineHooks.manage okta.logStreams.read okta.logStreams.manage okta.trustedOrigins.read okta.trustedOrigins.manage okta.domains.read okta.domains.manage okta.networkZones.read okta.networkZones.manage okta.brands.read okta.brands.manage okta.templates.read okta.templates.manage okta.linkedObjects.read okta.linkedObjects.manage okta.userTypes.read okta.userTypes.manage okta.profileMappings.read okta.profileMappings.manage okta.apiTokens.read okta.apiTokens.manage okta.rateLimits.read okta.rateLimits.manage okta.threatInsights.read okta.threatInsights.manage okta.agentPools.read okta.agentPools.manage okta.emailDomains.read okta.emailDomains.manage okta.realms.read okta.realms.manage okta.deviceAssurance.read okta.deviceAssurance.manage okta.captchas.read okta.captchas.manage okta.pushProviders.read okta.pushProviders.manage okta.principalRateLimits.read okta.principalRateLimits.manage okta.uischemas.read okta.uischemas.manage okta.identitySources.read okta.identitySources.manage okta.governance.accessRequests.read okta.governance.accessRequests.manage` — the CLI does not validate scopes; it passes them through.

## Task 1: crypto + token client (src/okta/oauth.ts, tests/oauth.test.ts, commit `feat: oauth client-credentials token client with private_key_jwt and dpop`)

- `export interface OAuthProfile { url: string; clientId: string; privateKey: JsonWebKey | string /* PEM */; kid?: string; scopes: string[]; dpop?: boolean }`.
- `importPrivateKey(key: JsonWebKey | string): Promise<{ key: CryptoKey; alg: "RS256" | "ES256"; kid?: string; publicJwk?: JsonWebKey }>` using `crypto.subtle.importKey` (`jwk` or `pkcs8` from PEM; strip header/footer, base64-decode). RSA → RS256 (`RSASSA-PKCS1-v1_5`, `SHA-256`); EC P-256 → ES256. For DPoP the ephemeral key pair is generated with `crypto.subtle.generateKey` (EC P-256) once per process and its public JWK exported.
- `signJwt(header, claims, key, alg): Promise<string>` (base64url, compact serialization). `b64url()` helper. `jti` from `crypto.randomUUID()`.
- `clientAssertion(profile, tokenEndpoint, now)`; `dpopProof({ htm, htu, nonce?, ath?, key, publicJwk, alg })`.
- `class OAuthTokenSource { constructor(profile, opts: { fetch?, now?, cache?: TokenCache }) ; async token(): Promise<{ accessToken: string; tokenType: "Bearer" | "DPoP"; expiresAt: number }> }` — caches in memory and, via `TokenCache` (`src/okta/token-cache.ts`: JSON file next to the config file, `okta-cli/tokens.json`, mode 0600, keyed by `${url}|${clientId}|${scopes.join(" ")}`; skip cache when `OKTA_CLI_NO_TOKEN_CACHE=1`), refreshes 60 s before expiry. Handles the `use_dpop_nonce` retry once. On any other non-200 → `CommunicationError("OAUTH_ERROR: <error>: <error_description>")` (exit 255).
- Tests (mock `fetch`): assertion claims/header decoded and checked (`aud`, `iss`, `sub`, `exp-iat == 300`, `kid`); RS256 signature verified with `crypto.subtle.verify` using the public key; ES256 path; DPoP nonce dance produces a second request with `DPoP` header whose payload has `nonce` and `htu`; cache hit avoids a second token request; expired cache refreshes; error mapping.

## Task 2: client integration (src/okta/client.ts, src/config.ts, src/cli/context.ts; tests/client-oauth.test.ts; commit `feat: bearer/dpop auth in OktaClient, oauth profiles in config`)

- `OktaClient` constructor gains a second form: `new OktaClient(url, auth: { kind: "ssws"; token } | { kind: "oauth"; source: OAuthTokenSource }, opts)` — keep the existing `(url, token, opts)` signature working (string → ssws). `send()` obtains the token per request (cached), sets `Authorization: Bearer|DPoP …`; for DPoP also sets the `DPoP` proof header (with `ath`) and, on a 401 whose `WWW-Authenticate` contains `use_dpop_nonce`, retries once with the `dpop-nonce` header value. On 401 `invalid_token` with an OAuth profile: drop the cached token, fetch a fresh one, retry once.
- `-v` logging never prints Authorization/DPoP header values.
- Config profile shape (src/config.ts): SSWS profiles unchanged `{ url, token }`; OAuth profiles `{ url, auth: "oauth", clientId, kid?, privateKey: <JWK object or PEM string> | privateKeyFile: <path>, scopes: string[], dpop?: boolean }`. `resolveProfile()` returns a discriminated union; `Ctx.getClient` builds the matching client. Env overrides: `OKTA_URL` + `OKTA_TOKEN` (ssws, existing) or `OKTA_URL` + `OKTA_CLIENT_ID` + (`OKTA_PRIVATE_KEY` | `OKTA_PRIVATE_KEY_FILE`) + `OKTA_SCOPES` (space separated) + optional `OKTA_KID`, `OKTA_DPOP=1`.
- Tests: mock server checks `Authorization: Bearer tok` on `/api/v1/users`; DPoP path: server returns 401 + `WWW-Authenticate: DPoP error="use_dpop_nonce"` + `dpop-nonce: n1` once, then 200 — assert the retried request has `Authorization: DPoP tok` and a `DPoP` header whose decoded payload has `nonce: "n1"`, `ath`, `htm: "GET"`, `htu` without query; config parsing of both profile shapes and the env overrides; `config list` masks nothing sensitive beyond what it does today (shows `oauth <clientId>` in the token column).
