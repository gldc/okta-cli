# okta-cli 19.2.0: remaining API families

**Goal:** Cover every remaining path family of the pinned Okta management spec (2026.08.4) that 19.1.0 skipped: brands/customization, security & identity (SSF, security events providers, threats, bot/attack protection, push providers, device integrations/posture checks, email servers, DR), agent pools, identity sources, OAuth client roles, IAM governance, org preferences/privacy extras, UI schemas, first-party app settings, directories, privileged access, OIN integrations, well-known endpoints.

**Conventions:** identical to docs/superpowers/plans/2026-09-12-more-endpoints.md "Conventions" (read that section) plus:
- Paths outside `/api/v1` are called with `client.xxx(path, { basePath: "/attack-protection/api/v1" })` etc. (client.buildUrl supports `basePath`; `""` means no prefix). `knownPath()` in src/okta/spec-paths.ts must be extended so paths starting with `/attack-protection/`, `/integrations/`, `/security/`, `/privileged-access/`, `/okta-personal-settings/`, `/webauthn-registration/` are matched as full paths (add those prefixes to its condition) — do this in Task 1 with a test.
- Multipart uploads (logo, favicon, background image, OIN logo): add `OktaClient.upload(path, fieldName, filePath, opts?)` in src/okta/client.ts that builds a `FormData` with `Bun.file(filePath)`, sends POST **without** the JSON Content-Type header (let fetch set the multipart boundary), keeps Authorization/Accept, handles 429 like `request`, and returns parsed JSON (or undefined on 204). Test with the fixture server reading `await req.formData()`. Do this in Task 1.
- "get/set" pairs for singleton settings: `<thing>` prints the object (default JSON since fields vary); `<thing>-set -b/-s` writes with the method the spec says (PUT/POST/PATCH — check `schema.d.ts` operations for the path).
- Commands with side effects that are hard to undo (`dr failover`, `dr failback`, `ssf stream-delete`, `email-servers delete`) behave like every other delete: no interactive confirm (the Python tool never confirmed either).
