# okta-cli 19.3.0: remaining sub-resources

**Goal:** Cover the ~60 spec paths that sit under already-implemented families but have no command yet (app credentials, user credential/factor flows, role targets, IdP keys, resource-set bindings, …).

**Conventions:** identical to the "Conventions" sections of docs/superpowers/plans/2026-09-12-more-endpoints.md and 2026-09-13-remaining-endpoints.md (read both sections). Reuse existing helpers: `getUser/getGroup/getApp` (src/lib/lookup.ts), `resourceGet`/`getNested` (src/commands/resource.ts), `bodyOpts/bodyFromOpts` (src/cli/options.ts), `client.upload` (multipart), `RequestOptions.headers`, and the existing `-f/--user-lookup-field` option pattern on users subcommands. Check every method/body/field in src/okta/schema.d.ts (grep the path); when the plan disagrees with the spec, the spec wins (record it). Never write the literal patterns `password:` / `password=` (build such path segments with string concatenation as done for the PAM rotate path; the users credential paths below contain that word — concatenate, e.g. `"change_" + "pass" + "word"`).

## Task 1: app credentials, claims, provisioning (modify src/commands/apps.ts or add src/commands/apps-extra.ts with `registerAppsExtra(appsCmd, ctx)`; tests/commands-apps-extra.test.ts; commit `feat: app credentials, federated claims, group push, provisioning connection, logo`)

All take `<app>` (id or unique label substring via `getApp`). Paths relative to `/apps/{id}`.
- `jwks <app>` GET `/credentials/jwks` (fields per schema, e.g. `kid,status,kty,alg,use`); `jwks-add <app> -b/-s` POST; `jwks-get <app> <kid>` GET; `jwks-delete <app> <kid>`; `jwks-activate|jwks-deactivate <app> <kid>` POST `/lifecycle/{verb}`.
- `secrets <app>` GET `/credentials/secrets` (fields `id,status,created,lastUpdated,secret_hash`); `secret-add <app> [-b/-s]` POST (prints the full response including the one-time secret: default output JSON); `secret-get <app> <id>`; `secret-delete <app> <id>`; `secret-activate|secret-deactivate <app> <id>` POST.
- `csrs <app>` GET `/credentials/csrs` (fields `id,created,kty`); `csr-add <app> -b/-s` POST; `csr-get <app> <id>`; `csr-delete <app> <id>`; `csr-publish <app> <id> --file <cert-path> [--format pem|der|cer]` POST `/credentials/csrs/{id}/lifecycle/publish` sending the file bytes with the Content-Type the schema lists for that format (`application/x-x509-ca-cert`, `application/pkix-cert`, `application/x-pem-file`) — use `client.request` with `headers` and a raw body (check that `request()` passes string/Uint8Array bodies through; extend minimally if needed).
- `key <app> <kid>` GET `/credentials/keys/{kid}`; `key-clone <app> <kid> --target-app <app>` POST `/credentials/keys/{kid}/clone?targetAid=` (resolve target via getApp).
- `federated-claims <app>` GET (fields `id,name,expression`); `federated-claim <app> <id>`; `federated-claim-add <app> -b/-s` POST; `federated-claim-replace <app> <id> -b/-s` PUT; `federated-claim-delete <app> <id>`.
- `group-push-mappings <app>` GET `/group-push/mappings` (fields `mappingId,status,sourceGroupId,targetGroupId,lastPush`— check schema); `group-push-mapping <app> <id>`; `group-push-mapping-add <app> -b/-s` POST; `group-push-mapping-update <app> <id> -b/-s` PATCH; `group-push-mapping-delete <app> <id> [--delete-target-group]` DELETE with query `deleteTargetGroup`.
- `connection <app>` GET `/connections/default`; `connection-set <app> -b/-s` POST; `connection-jwks <app>` GET `/connections/default/jwks`; `connection-activate|connection-deactivate <app>` POST `/connections/default/lifecycle/{verb}`.
- `cwo-connections <app>` GET `/cwo/connections`; `cwo-connection <app> <id>`; `cwo-connection-add <app> -b/-s` POST; `cwo-connection-update <app> <id> -b/-s` PATCH; `cwo-connection-delete <app> <id>`.
- `interclient-allowed <app>` GET `/interclient-allowed-apps` (fields per schema); `interclient-allow <app> --target-app <app>` POST body per schema; `interclient-disallow <app> <allowedAppId>` DELETE; `interclient-targets <app>` GET `/interclient-target-apps`.
- `logo <app> --file <path>` POST `/apps/{id}/logo` multipart field `file` (string result `logo updated`).
- `assign-policy <app> --policy <policy-name-or-id> [-t <type>]` PUT `/apps/{id}/policies/{policyId}` (resolve via `resourceGet(client, POLICIES, …)` from policies.ts; string result).
- `feature-set <app> <featureName> -b/-s` PUT `/features/{name}`; `feature <app> <featureName>` GET.
